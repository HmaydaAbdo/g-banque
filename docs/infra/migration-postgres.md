# Migration MySQL 8 → PostgreSQL 18 — G-Banque

> Document technique (infra/exploitation). Décision HMAYDA du 10/10/2026 : PostgreSQL 18 remplace MySQL 8 pour le
> développement, les tests, la CI et la production. Règles de travail : `conventions/database.md`.

---

## Principe

1. Le schéma PostgreSQL est créé **par Flyway** au premier démarrage du backend (`V1__schema_initial.sql`, généré
   depuis les entités, puis les vues `R__`).
2. Les données de production sont **versées** ensuite depuis un export phpMyAdmin de la base MySQL, par l'outil
   `sql/migration-postgres/` : un MySQL temporaire charge l'export, un conteneur Python copie chaque table dans
   PostgreSQL **en une seule transaction** (tout ou rien), recale les compteurs et compare les volumes table par table.

Aucun outil n'est à installer : tout tourne dans des conteneurs (Docker requis).

---

## Procédure (base PostgreSQL vide)

```bash
docker compose up -d postgres
docker compose up -d --build backend     # 1er démarrage : Flyway crée le schéma
docker compose stop backend
python sql/migration-postgres/migrer_vers_postgres.py "C:/chemin/vers/export.sql"
docker compose up -d
```

* L'outil refuse de s'exécuter si la base PostgreSQL contient déjà des utilisateurs (jamais d'écrasement).
* Les configurations par défaut créées au 1er démarrage (CMT, leasing, lignes fonctionnelles) sont remplacées par
  celles de la production.
* En cas d'erreur, la transaction est annulée : la base reste vide, corriger puis relancer.
* Durée constatée : ~5 min 30 pour l'export de production du 10/10/2026.

## Conversions et choix

| Sujet | MySQL | PostgreSQL | Choix |
|---|---|---|---|
| Comparaison de texte | `utf8mb4_*_ci` : insensible casse + accents | sensible par défaut | collation `ci_ai` sur le texte libre (cf. `conventions/database.md`) : comportement identique |
| Booléens | `bit(1)` | `boolean` | converti |
| Horodatages (`OffsetDateTime`, `Instant`) | `datetime(6)` en UTC | `timestamp with time zone` | valeurs lues comme UTC |
| Binaires (logos, `date_rapprochement`) | `longblob`, `varbinary` | `bytea` | copiés octet pour octet |
| Énumérations | `ENUM(...)` | `varchar` + `CHECK` | `commission.operation` accepte aussi `Importation` (8 lignes, cf. TODO) |
| Identifiants | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | redémarrés à max(id)+1 |
| Séquences | tables `*_seq` | séquences | Envers et Spring Batch recalées sur la production |
| Spring Batch | tables `BATCH_*` | script officiel PostgreSQL | historique des jobs copié |
| Colonnes facultatives en prod, obligatoires dans les entités | NULL autorisé (60 colonnes) | alignées sur la prod en V1 | une seule valeur NULL réelle (décompte 3) ; à resserrer par V2 (cf. TODO) |

Colonnes de production absentes du code, **non migrées** (vérifié : aucune donnée utile) : `contrat_leasing`
`fichier_pdf_contenu` / `nom_fichier_pdf` (vides sur les 121 contrats), `date_upload_pdf` (12 dates sans fichier),
quelques colonnes d'audit d'anciennes versions (`organisme_leasing_aud`, `contrat_leasing_aud`).
