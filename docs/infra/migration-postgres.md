## Déroulé

1. L'outil de migration (supprimé du dépôt le 12/10/2026, la migration étant faite) créait le schéma **en version 1** avec
   l'image Flyway officielle (mêmes fichiers `db/migration` que le backend), puis y versait les données d'un export
   phpMyAdmin de la base MySQL **en une seule transaction** (tout ou rien), recalait les compteurs et comparait les
   volumes table par table. Les données entraient en V1, avant les migrations qui resserrent les contraintes.
2. Au démarrage, le backend a appliqué les migrations suivantes **sur les données migrées** (V2 : libellé du décompte
   n° 3 puis 60 colonnes rendues obligatoires), recréé les vues `R__`, puis Hibernate a validé le schéma.

Si une nouvelle migration depuis un export MySQL redevenait nécessaire (le TODO conserve l'ancienne base MySQL jusqu'à
la validation par la Finance), l'outil reste récupérable dans l'historique git :
`git show a9563902^:sql/migration-postgres/migrer_vers_postgres.py` (dossier `sql/migration-postgres/` du commit `a9563902^`).

## Conversions et choix

| Sujet | MySQL | PostgreSQL | Choix |
|---|---|---|---|
| Comparaison de texte | `utf8mb4_*_ci` : insensible casse + accents | sensible par défaut | collation `ci_ai` sur le texte libre (cf. `conventions/database.md`) : comportement identique |
| Booléens | `bit(1)` | `boolean` | converti |
| Horodatages (`OffsetDateTime`, `Instant`) | `datetime(6)` en UTC | `timestamp with time zone` | valeurs lues comme UTC |
| Binaires (logos, `date_rapprochement`) | `longblob`, `varbinary` | `bytea` | copiés octet pour octet |
| Énumérations | `ENUM(...)` | `varchar` + `CHECK` | `commission.operation` accepte aussi `Importation` (8 lignes, cf. TODO) |
| Identifiants | `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` | redémarrés à max(id)+1 |
| Séquences | tables `*_seq` | séquences | Envers et Spring Batch recalées sur la production |
| Spring Batch | tables `BATCH_*` | script officiel PostgreSQL | historique des jobs copié |
| Colonnes facultatives en prod, obligatoires dans les entités | NULL autorisé (60 colonnes) | facultatives en V1, **obligatoires en V2** | un seul NULL réel : décompte n° 3 → « DP N°1 SIDI BERNOUSSI » (format des décomptes du même marché, décision HMAYDA) |

Colonnes de production absentes du code, **non migrées** (vérifié : aucune donnée utile) : `contrat_leasing`
`fichier_pdf_contenu` / `nom_fichier_pdf` (vides sur les 121 contrats), `date_upload_pdf` (12 dates sans fichier),
quelques colonnes d'audit d'anciennes versions (`organisme_leasing_aud`, `contrat_leasing_aud`).
